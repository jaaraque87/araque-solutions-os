# Writing Beats
Moldear un artículo como un journey de **beats**, estilo choose-your-own-adventure. El usuario elige un beat de arranque, luego un beat siguiente, luego el próximo — hasta que el artículo llega a un final natural. El usuario pasa un markdown de material crudo. Si no dijo dónde guardar, preguntar una vez y recordar el path.

## Journey beat-by-beat
1. Escribir 2–3 **starting beats** candidatos del material crudo (cada uno un entry point distinto).
2. Cuando el usuario elige, escribir **solo ese beat** al archivo (un beat puede ser una oración o varios párrafos).
3. Re-leer el archivo desde disco.
4. Ofrecer 2–3 **next beats** candidatos (direcciones distintas).
5. Loop 2–4 hasta un final natural.

## Qué es un beat
Un movimiento en el journey. Hace una cosa — setea una escena, aterriza un punto, hace una pregunta. Tamaño según lo que necesita: una oración si eso es todo ("And then nothing happened for three weeks.") · un párrafo corto si necesita setup · varios párrafos si es una viñeta/argumento/ejemplo autocontenido. Si un "beat" necesita 5 párrafos y 3 subheadings, no es un beat — son dos beats pegados.

## Escribir un beat
Escribir **solo ese beat** (no el siguiente). Traer material del pile: parafrasear, partir, recombinar, o citar.

## Terminar el journey
El artículo termina cuando el journey está completo — NO cuando el pile se vació. La mayoría de los piles dejarán material sobrante.

## Writing rhythm
Appendear un beat a la vez, nunca escribir adelante · re-leer el archivo desde disco antes de cada escritura (preservar ediciones del usuario absolutamente) · si el usuario edita un beat previo sustancialmente, dejar que cambie lo que viene · si dice "rewrite that beat" / "go back and try a different beat 3", hacerlo (editar in place).
